# THE LUXE — Lean Context Discipline

This is a **portable repo-specific workflow**, inspired by efficient engineering practice; it is **not** the third-party Ponytail plugin, and does not reproduce Ponytail hooks or dynamic mode switches.

- Start with task ID, goal, scoped paths and the shortest authoritative references: `AGENTS.md`, decision + next actions, specific issue; read more only when required.
- Inspect via filenames/search and precise file sections before reading entire directories; avoid repeatedly loading large logs, PDFs and old chat history.
- Preserve a short, structured handoff: current SHA/branch, decisions already approved, tested behavior, outstanding failures and next action. Place durable facts in issue/PR or project memory, not conversation transcripts.
- Prefer one agent per independent task, incremental tests while coding, full required gates at acceptance. Never optimize credits by skipping tenant/authorization tests, failing checks or explicit founder approval.
- Avoid conflicting speculative branches or simultaneous agents editing the same contract. Summarize concise facts rather than verbose narration, but report exact test results and key risk evidence.
- If the external Ponytail plugin is installed locally, it can add local hooks/commands; these do **not** automatically execute in Copilot Cloud. Do not claim parity for third-party extensions without verifying them.
