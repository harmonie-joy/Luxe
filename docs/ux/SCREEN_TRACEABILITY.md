## Cross-layer completeness audit and exact handoff

- **Shell:** session journey → loading/sign-in/outage/verified identity states → `/api/auth/me/`, account/logout → User/Workspace/Membership. Component/HTTP and synthetic browser tests support presentation/navigation; backend auth remains authoritative. These captures do not prove live session isolation.
- **Continue work / Single-Post Dashboard:** journey requires actual title, goal, stage, next action and save state. Project/ContentItem/ExecutionCheckpoint and workspace/version authorization exist on master; frontend list/context/editor/persistence verification are missing. Mark incomplete until #53 and the independent #54 gate supply their evidence.
- **Approval:** active BrandVoice is insufficient. New items need the exact active, human-approved version; `/api/brand-voices/{id}/approve/` is explicit acceptance, not activation. Existing voice tools are not full accepted Creator DNA. #53 must show approved/unapproved/unknown truthfully and keep the pinned voice on resume.
- **Contract constraints:** workspace-filtered Project/item lists are arrays; context contains `item`, `checkpoint`, `brandVoice`. Writes are snake_case; reads camelCase. Stages `idea`/`drafting` only. Saved title is read-only. Checkpoint POST includes full snapshot, `expected_revision`, UUID `client_request_id`; handle `stale_revision` and `idempotency_key_reused`409s. An exact retry may acknowledge an older revision; reconcile without losing newer input. Initial creation lacks client idempotency: prevent duplicate pending submissions and reconcile ambiguous failure before retry.
- **Legacy tools:** real Brand Voice/brief/draft APIs coexist with demo/fallback states; they cannot substantiate new ContentItem, Gallery or publishing claims. Quick Draft stays unavailable until its live entry is independently verified.
