# Pilot Demo Checklist and Feedback

Use this checklist to run the same Creator/CEO workflow with each pilot
participant. Record feedback with the template at the end. Use a demo workspace
and synthetic content; do not put credentials, private creator/client material,
or other sensitive information in feedback notes.

## Before the demo

- [ ] Confirm the demo environment is available and sign in with the intended demo account.
- [ ] Confirm the account is in the intended Workspace and has a BrandVoice version available for review.
- [ ] Prepare a simple, synthetic content goal and note the participant's usual time for a comparable task.
- [ ] Explain that this is a product pilot, not a production-readiness or compliance certification.
- [ ] Ask the participant to describe their current workflow and how they measure the time it takes.

## Demo walkthrough

- [ ] Start at Creator Home and orient the participant to saved work and the next action.
- [ ] Review the available BrandVoice version and explicitly accept that version before using it as context.
- [ ] Create a Project/ContentItem for the prepared goal, using the accepted BrandVoice context.
- [ ] Add or review the item's goal, stage, decisions, open questions, and next action.
- [ ] Save a checkpoint and show the saved state.
- [ ] Refresh or leave and return to the item; where practical, sign out and back in to show persisted resume.
- [ ] Verify the item resumes with its saved context and pinned BrandVoice version.
- [ ] Ask the participant what was clear, confusing, useful, or missing. Capture observations in the feedback template.
- [ ] Close by restating what the demo did and did not demonstrate; do not imply that draft content is approved for publishing.

## Known limitations to disclose

- The pilot flow covers saved Project/ContentItem context and checkpoints; it is not the full Creator DNA or end-to-end creator operating system.
- BrandVoice acceptance is version-specific and separate from activating a voice. It is not final approval of generated content.
- Checkpoint conflicts require the user to resolve the conflict deliberately; the app does not automatically merge edits. Unsaved edits are not offline or browser-crash recovery.
- Initial item creation does not guarantee exactly-once behavior. If the result of a create action is uncertain, check saved work before retrying to avoid a duplicate.
- The Media Finalizer is not complete, and Page 10A remains provisional. Do not present the media workflow or current page design as final.
- The demo does not demonstrate direct publishing, production readiness, or legal/compliance certification.
